What do these results mean?
Matching and mismatching statuses apply only to an explicitly printed weekday next to a date. DATE ONLY is informational and never proof of a missing weekday. REVIEW means the wording or extraction does not support a confident match. The auditor checks dates against the Gregorian calendar. An OCR attempt does not guarantee that every printed date was recognized. Incomplete page coverage or ambiguous text requires human review. Source files are never overwritten.

How is the result calculated?
The calendar residue is W = (C + Y + M + D) mod 7, with Sunday = 0 and Saturday = 6. The month contribution depends on leap-year status. The optimized GCF-400 lookup caches the combined year and month contributions.

How GCF Works



        GCF turns a Gregorian date into four understandable contributions—century, year, month, and day—
        and combines them in a seven-day cycle. The goal of this section is not only to give the answer,
        but to show why each number is used and how one step leads to the next.
      


W ≡ C + Y + M + D (mod 7)






1




Start with a valid Gregorian date


Enter the year, month, and day. First make sure the date actually exists and falls within the app's supported range of positive Common Era years 1–9999.








2




Split the year into century and year position


For a year N, compute c = ⌊N/100⌋ for the completed centuries and y = N mod 100 for the years within the current century. This lets GCF handle long-term and within-century shifts separately.








3




Find the century code C


Use c mod 4 and the repeating GCF century pattern: 0 → 7, 1 → 5, 2 → 3, 3 → 1. The four-position repetition follows the Gregorian calendar's 400-year cycle.








4




Find the year code Y


Use Y ≡ y + ⌊y/4⌋ (mod 7). The y term represents one weekday shift for each completed year, while ⌊y/4⌋ counts the additional leap-year contributions within the year position.








5




Check the Gregorian leap-year rule


A year is a leap year when it is divisible by 400, or divisible by 4 but not by 100. This matters because January and February use different month codes in a leap year.








6




Choose the month code M


The common-year codes are generated from the January anchor and the lengths of the preceding months, reduced modulo 7. In leap years, January and February are each reduced by 1 because the extra February day has not yet occurred for those dates.








7




Use the day value D


The day of the month is inserted directly. For example, the 24th day uses D = 24.








8




Combine the four components


Add C + Y + M + D, then reduce the total modulo 7. The remainder is the GCF weekday code.








9




Translate the code into the weekday


GCF uses 0 = Sunday, 1 = Monday, through 6 = Saturday. The app shows both the numerical code and the weekday name.

Why the century code repeats



        The Gregorian leap-year pattern repeats every 400 years. In each 400-year cycle there are 97 leap years,
        giving 146,097 total days, which is exactly 20,871 weeks. Because the full number of weeks is an integer,
        the weekday pattern returns to the same position after 400 years.
      


Why the year code uses a floor



        A common year has 365 ≡ 1 (mod 7) days, while a leap year has 366 ≡ 2 (mod 7) days.
        Therefore, each completed year contributes one shift and each completed leap year contributes one additional shift.
        The floor symbol ⌊y/4⌋ counts only complete four-year groups. For example,
        ⌊83/4⌋ = 20, not 20.75.
      


Why the month codes follow a pattern



        The next month's code is obtained by adding the length of the current month and reducing modulo 7.
        For example, January starts with code 6; since January has 31 days and 31 mod 7 = 3,
        February's code is 6 + 3 ≡ 2 (mod 7). The same process continues through the year.
